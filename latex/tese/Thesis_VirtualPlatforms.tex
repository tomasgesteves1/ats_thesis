\chapter{Virtual Platforms and Simulation Environment}
\label{chapter:virtual_platforms}

This chapter describes the simulation environment and the virtual vehicle models used to validate the cooperative control architecture. To bridge the gap between theory and practical application, the multi-agent system is simulated with high physical fidelity. The setup consists of three main elements: the WAM-V surface vessel, the x500 quadrotor, and the flexible tether that connects them. The following sections detail the simulation tools, the physical characteristics of each vehicle, the cable model, and the integration of the overall system.

% =========================================================================
\section{Simulation Framework}
\label{sec:sim_ecosystem}

The simulation is built on a modular software stack that handles physics resolution, multi-body constraints, autopilot emulation, and communication bridges, as shown in Figure~\ref{fig:software_architecture}.

    \subsection{Gazebo and Virtual RobotX (VRX)}
    The core simulator is Gazebo Harmonic \cite{koenig2004gazebo}. It manages multi-body physics, rendering, and sensor emulation using the DART engine \cite{lee2018dart} with a time step of $0.004\,\text{s}$ ($250\,\text{Hz}$). Maritime conditions are simulated using the Virtual RobotX (\gls{vrx}) framework \cite{bingham2019vrx}, which provides custom tools to model wave dynamics, buoyancy, wind, and hydrodynamic forces.

    \subsection{MoorDyn Cable Physics}
    Tether forces and cable dynamics are calculated using the MoorDyn library \cite{hall2015moordyn}. This tool uses a lumped-mass approach, dividing the cable into a series of nodes connected by spring-damper segments. It computes longitudinal stiffness, internal damping, gravity, buoyancy, and drag forces acting along the line.

    \subsection{PX4 Software-in-the-Loop (SITL)}
    To capture realistic flight behavior, the quadrotor's autopilot is simulated using the PX4 firmware \cite{meier2015px4} running in Software-in-the-Loop (\gls{sitl}) mode. The firmware runs on the host computer, receiving state feedback from Gazebo and commanding the virtual motor models, which replicates the behavior of the real flight control unit.

    \subsection{Communication Bridges}
    Two main interfaces connect the control algorithms with the simulation environment. First, the \texttt{ros\_gz\_bridge} handles bidirectional data flow between Gazebo and \gls{ros}~2 \cite{macenski2022ros2}, transmitting sensor feedback and USV actuator commands. Second, the Micro XRCE-\gls{dds} middleware links the PX4 internal \gls{uorb} messaging system with the \gls{ros}~2 network. This bridge translates high-rate attitude telemetry and offboard control commands, allowing custom ROS 2 nodes to interface with the flight controller.

\section{WAM-V Catamaran}
\label{sec:usv_model}

The selection of the surface vehicle is a key design choice in cooperative marine-aerial systems. For this project, we employ the Wave Adaptive Modular Vessel (WAM-V), a unique catamaran configuration consisting of two inflatable hulls connected to a central deck structure. Unlike rigid-hulled vessels, the WAM-V utilizes an articulating suspension system that isolates the payload deck from wave-induced pitch and roll movements, ensuring a relatively stable deck.

To bridge the gap between simulation and real-world deployment, the virtual platform is based on the standardized model from the Virtual RobotX (VRX) simulation framework \cite{bingham2019vrx}. Sourced directly from the official robot description packages, this virtual model matches the physical parameters of the real WAM-V used in international maritime robotics competitions.

The WAM-V catamaran is particularly suited for our tethered UAV-USV marsupial system. First, its dual rear steerable thrusters provide exceptional maneuverability, allowing for precise omnidirectional vectoring during path-following and relative positioning. Second, the spacious and flat central deck provides a reliable landing platform to recover the quadrotor. These features make the WAM-V an ideal mobile base station for coordinate flights and autonomous drone retrieval under active wave conditions. The virtual catamaran representation is shown in Figure~\ref{fig:wamv_render}.

Structurally, this 16-foot catamaran has an overall length of $4.90\,\text{m}$ and an overall beam of $2.40\,\text{m}$. The central payload deck, measuring $1.85\,\text{m}$ in length and $1.00\,\text{m}$ in width, is supported by two parallel hulls at about $1.25\,\text{m}$ above the water surface, as illustrated in Figure~\ref{fig:wamv_schematic}.

    In the simulator, the boat's total mass is modeled at $259.10\,\text{kg}$, which accounts for the catamaran chassis, the onboard batteries, the dual propulsion steering pods, and the sensory payloads.

    \subsection{Propulsion Configuration}
    Instead of using a traditional rudder, the WAM-V steers by rotating its two rear propulsion pods, known as azimuthing thrusters, which are positioned at the stern of each hull, as shown in Figure \ref{fig:wamv_render}. The control system developed in this work restricts their steering angle to a physical limit of $\pm 30$ degrees to avoid twisting the power cables, with the steering rate limited to $1.0\,\text{rad/s}$.

    The thrust force is adjusted by changing the propeller speed. The maximum thrust limit of each motor is set to $510.0\,\text{N}$ in the forward direction. This represents the physical capabilities of commercial electric outboards commonly used on the WAM-V 16 in the RobotX competition, such as the Torqeedo Cruise 2.0 \cite{torqeedo_cruise_manual}. Additionally, the motors exhibit reduced efficiency in reverse due to their propeller blade geometry, which is modeled using a reverse thrust efficiency multiplier of $0.746$, restricting the maximum reverse thrust to $-380.0\,\text{N}$. 

    \subsection{Buoyancy and Hydrodynamics}
    Buoyancy is simulated by continuously calculating the volume of the hulls submerged under the water surface. The sea surface is modeled using Gerstner waves, and the simulator checks the hull geometry against the wave profile to resolve the hydrostatic forces. This yields natural lifting forces and moments, causing the catamaran to pitch and roll realistically in response to wave excitation.

    Hydrodynamic drag is represented through a combination of linear damping coefficients for low-speed viscous resistance and quadratic coefficients to capture high-speed form drag. These drag forces and moments are applied across all six degrees of freedom, as detailed in Table~\ref{tab:usv_damping_parameters}, ensuring the catamaran exhibits natural deceleration when propulsion is cut off.

\section{x500 Quadrotor}
\label{sec:uav_model}

The aerial platform is modeled after the Holybro x500 quadrotor frame. It is represented as a rigid body with 6 \glspl{dof}, consisting of a central hub and four rotating propeller links.

    \subsection{Physical Properties and Aerodynamics}
    The quadrotor has a total mass of $2.06\,\text{kg}$, consisting of a $2.00\,\text{kg}$ central body and four rotor links of $0.016\,\text{kg}$ each. The moments of inertia are $I_{xx,a} = 0.0217\,\text{kg}\cdot\text{m}^2$ for roll, $I_{yy,a} = 0.0217\,\text{kg}\cdot\text{m}^2$ for pitch, and $I_{zz,a} = 0.0400\,\text{kg}\cdot\text{m}^2$ for yaw. The propulsion system consists of four brushless motors in an X-configuration with $0.254\,\text{m}$ (10-inch) propellers.
    
    Rotor thrust and torque are calculated using a multicopter motor model based on propeller rotational speed. The motor constant is set to $8.55 \times 10^{-6}\,\text{N}/(\text{rad/s})^2$ and the torque constant is $0.016\,\text{m}$. The maximum speed of the propellers is limited to $1000\,\text{rad/s}$. Motor responsiveness includes a speed lag modeled with time constants ($\tau_{up} = 0.0125\,\text{s}$ and $\tau_{down} = 0.0250\,\text{s}$). The physical and aerodynamic parameters are summarized in Table~\ref{tab:uav_parameters}.

    \subsection{Autopilot and Flight Control}
    The inner-loop attitude of the quadrotor is stabilized by a PX4 autopilot running in Software-in-the-Loop (\gls{sitl}) mode. This setup runs the official firmware on the host computer, communicating with Gazebo through a lockstep synchronization protocol to ensure time consistency. The autopilot receives state feedback and commands motor velocities via cascaded PID loops. A Micro XRCE-\gls{dds} bridge connects this system to the ROS 2 workspace, allowing outer-loop NMPC algorithms to send high-level attitude and velocity setpoints.

\section{Tether Representation and Coupling}
\label{sec:tether_coupling}

The physical coupling between the WAM-V catamaran and the x500 quadrotor is established by a flexible tether. The tether is managed by an active winch system mounted on the catamaran's deck. The simulation supports two distinct tether representations depending on the evaluation requirements.

    \subsection{Tether Representation Models}
    The tether can be simulated using a multibody joint chain or a lumped-mass model. The multibody joint chain is resolved in Gazebo. The lumped-mass model is resolved using the MoorDyn library.
    
    The multibody joint chain is used for visual rendering and contact collisions. It consists of a chain of $30$ rigid cylindrical links connected by spherical ball joints. Each link has a radius of $0.01\,\text{m}$ and a mass of $0.02\,\text{kg}$. The total mass of the nominal $5.0\,\text{m}$ chain is $0.60\,\text{kg}$. Joint damping is set to $2.0\,\text{N}\cdot\text{s/m}$ and friction to $0.1\,\text{N}\cdot\text{m}$. The first and last links are scaled to $20\%$ of their length to prevent numerical instability at the attachment points.
    
    The MoorDyn lumped-mass model is used for high-fidelity tension propagation. The cable is discretized into $30$ mass nodes connected by spring-damper segments. The physical parameters represent an industrial micro-tether, with a diameter of $0.004\,\text{m}$, linear mass density of $0.020\,\text{kg/m}$, extensional stiffness of $EA = 100.0\,\text{N}$, bending stiffness of $EI = 2.0 \times 10^{-5}\,\text{N}\cdot\text{m}^2$, and damping ratio of $\zeta = 0.8$. Drag coefficients are set to $1.2$ transversely and $0.005$ axially. The physical properties are summarized in Table~\ref{tab:tether_parameters}.

    \subsection{Winch and Anchor Integration}
    The active winch is mounted on the WAM-V deck, offset by $\mathbf{p}_{a/v} = [-0.8, 0.0, 0.0]^T\,\text{m}$ from the center of gravity. The winch dynamically spools the tether to adjust its unstretched length $L_{tether}$ between $1.5\,\text{m}$ and $50.0\,\text{m}$, with a maximum spooling speed of $10.0\,\text{m/s}$.
    
    The winch operates in two control modes. In geometric mode, the tether length is set to $115\%$ of the line-of-sight distance between the vehicles, with the slack factor preventing sudden tension spikes. In tension mode, a PD controller regulates the spooling rate to maintain a target tension of $T_{target} = 0.1\,\text{N}$, using a proportional gain of $K_p = 1.8\,\text{m/(s}\cdot\text{N)}$ and a derivative gain of $K_d = 0.1$.
    
    The calculated cable forces are applied directly to the anchor points. For the quadrotor, the force acts on its main base link, while on the catamaran, the force is applied at the winch location. This creates a bidirectional coupling between the vehicles. The tension force vector at the anchor is monitored in simulation to provide feedback for the winch controller.

\section{System Integration and Data Flow}
\label{sec:system_data_flow}

To coordinate the simulation, a centralized data flow architecture is implemented. The overall loop involves multiple distributed nodes. These nodes communicate using \gls{ros}~2 topics and services. The ground-truth state feedback is published by the Gazebo and PX4 \gls{sitl} instances. This telemetry is translated by the communication bridges and published to the \gls{ros}~2 network.
The control algorithms process this feedback to execute three main control loops. The \gls{usv} control loop operates at $10\,\text{Hz}$ using a Nonlinear Model Predictive Control (\gls{nmpc}) node. It receives the vessel's ground-truth odometry and calculates the virtual forces and moment $[X, Y, N]^T$. The thruster allocation block then maps these virtual forces to publish steering angles and motor thrust commands to Gazebo. The \gls{uav} control loop operates at $50\,\text{Hz}$ using a separate \gls{nmpc} node. It receives the drone's ground-truth telemetry and the relative \gls{usv} position to calculate collective thrust and attitude rates. These targets are published to the PX4 flight controller via Micro XRCE-\gls{dds}. The tether and winch loop operates at $50\,\text{Hz}$. The MoorDyn node updates the cable state by receiving vehicle poses from TF and publishing the calculated tension forces to Gazebo. Simultaneously, the winch controller computes the spooling rate command $\dot{L}_{tether}$ to update the unstretched length of the cable in MoorDyn.

This distributed closed-loop execution is synchronized. The synchronization ensures stable interactions between the vehicles and the tether.
